# 牙周图表OCR区域检测修复报告

## 问题诊断

### 原始问题
系统无法正确检测到 **Furcation（根分叉病变）** 数据，批量测试中8张图像的Furcation数据全部为0。

### 根本原因分析

#### 1. 区域重叠问题
通过调试脚本 `debug_furcation.py` 分析原始OCR输出，发现：

```
检测到的区域：
- pi_region (PI):     Y range: (667, 1612)  ← 范围过大！
- mobility_region:    Y range: (740, 1526)
- furcation_region:   Y range: (780, 1480)
- bop_region (BOP):   Y range: (986, 1750)
- pd_region (PD):     Y range: (1038, 1198)
```

`pi_region` 的Y范围 (667-1612) 覆盖了其他所有区域，导致：
- Y=759-773 的罗马数字本应是 `Mobility` 数据
- Y=775-816 的罗马数字本应是 `Furcation` 数据
- 但都被错误分配到了 `pi_region`

#### 2. 代码问题

**问题1：`_get_region_type` 方法的匹配逻辑**
```python
# 修复前：返回第一个匹配的区域
for region_name, region_data in regions.items():
    if y_min <= y <= y_max:
        return region_name  # 直接返回，不考虑其他区域
```

由于字典遍历顺序，`pi_region` 总是第一个被匹配，覆盖了其他区域。

**问题2：默认区域划分Bug**
```python
# 修复前：mobility_region 和 furcation_region 使用了相同的 y_range
'mobility_region': {
    'y_range': (int(h * 0.62), int(h * 0.74))  # 错误！
},
'furcation_region': {
    'y_range': (int(h * 0.62), int(h * 0.74))  # 相同！
}
```

## 修复方案

### 修复1：改进区域匹配逻辑

采用**最小范围优先**策略：当Y坐标同时属于多个区域时，选择范围最小的区域（最精确匹配）。

```python
def _get_region_type(self, y: int, regions: Dict) -> Optional[str]:
    """
    优先级策略：当区域重叠时，选择范围最小的区域（最精确匹配）
    """
    priority_order = [
        'pi_region',
        'mobility_region',
        'furcation_region',
        'bop_region',
        'pd_region'
    ]

    # 找出所有匹配的区域
    matching_regions = []
    for region_name in priority_order:
        if region_name not in regions:
            continue
        region_data = regions[region_name]

        if 'y_range' in region_data:
            y_min, y_max = region_data['y_range']
            if y_min <= y <= y_max:
                range_size = y_max - y_min
                matching_regions.append((region_name, range_size))

    # 返回范围最小的匹配区域
    if matching_regions:
        matching_regions.sort(key=lambda x: x[1])
        return matching_regions[0][0]

    return None
```

### 修复2：修正默认区域划分

基于 `handwrite3.jpg` 的实际检测数据调整区域比例：

```python
def _get_default_regions(self, w: int, h: int) -> Dict:
    """
    标准表格顺序（从上到下）：
    PI -> Mobility -> Furcation -> BOP -> PD
    """
    # 基于实际检测数据：PI: 24%, Mobility: 27%, Furcation: 29%, BOP: 36%, PD: 38-44%

    regions = {
        'pi_region': {
            'y_range': (int(h * 0.24), int(h * 0.27))
        },
        'mobility_region': {
            'y_range': (int(h * 0.27), int(h * 0.29))
        },
        'furcation_region': {
            'y_range': (int(h * 0.29), int(h * 0.36))
        },
        'bop_region': {
            'y_range': (int(h * 0.36), int(h * 0.40))
        },
        'pd_region': {
            'y_range': (int(h * 0.38), int(h * 0.45))
        },
    }
    return regions
```

## 进一步优化建议

### 1. PI数据识别率较低

**当前状态**：8张图像只检测到2个PI数据点

**原因分析**：
- PI区域的罗马数字可能被误识别为希腊字母π或其他符号
- 后处理中的罗马数字修正规则可能需要补充

**建议优化**：
```python
# 在 post_processor.py 中添加
ROMAN_MAP = {
    # 补充更多PI相关的修正
    'π': 'I',        # 希腊字母π
    'Π': 'I',        # 大写Π
    'n': 'I',        # 可能的误识别
    'r': 'I',
}
```

### 2. 表格上下半部分识别

**当前问题**：表格有上下两个半部分，分别重复相同的行。当前系统只处理了上半部分。

**建议方案**：
- 检测表格中间的分隔线（如"牙位"行）
- 为上下半部分分别建立区域映射
- 或者将上下半部分的数据进行合并

### 3. 使用PPOCRLabel进行标注

当检测精度不足时，可以使用PPOCRLabel进行半自动标注：

```bash
# 安装PPOCRLabel
cd PaddleOCR/PPOCRLabel
pip install -r requirements.txt
python PPOCRLabel.py --lang ch

# 重点标注
- 罗马数字（I°, II°, III°）
- 医学符号（+, -, ×）
- 特殊字符（π）
```

### 4. 模型微调

如果使用PPOCRLabel后仍不满意，考虑模型微调：

**数据准备**：
- 标注500+罗马数字样本
- 标注300+特殊符号样本

**微调流程**：
参考 `docs/模型微调指南.md`
